# Special courses — design

Date: 2026-10-01 · Status: awaiting user review · Sub-project A of 2 (sub-project B: [dictionary word pages](2026-10-01-dictionary-word-pages-design.md), built first).

## Goal

Add 32 stand-alone themed mini-courses ("Specials") that go deeper than the 69 main lessons on grammar, verbs, word fields and real-life German. Each is well explained, organised into chapters, and ends with its own quiz. They live in a findable place on the site.

Success criteria
- 32 specials at launch (the requirement is at least 25), each with 4–6 chapters, a final quiz of at least 12 questions, EN and FR throughout, and a pass mark.
- A learner can find the Specials from the top nav, the home page and the lessons they extend.
- Progress, XP, streak and review behave like lessons; passing a quiz is visible (badge on the hub and on the special's page).
- All wording is original. The coursebooks (Menschen, DaF Grammatiktrainer, PONS, Easy German) and web sources guide topic selection only; nothing is copied from them. Book pages are shown as "More in the textbook" links.

## Out of scope (v1)

- B2 content, user-authored specials, certificates, leaderboards.
- Changing the main lesson path or renumbering lessons.

## Design

### 1. Content model

A special is lesson-shaped so the player, exercise types, EN/FR fields and audio all work unchanged.

- Files: `content/specials/<slug>.ts`, one per special, validated with Zod at module load like lessons. `content/specials/index.ts` exports `specials` (parsed) and `getSpecial(slug)`.
- Type: `SpecialSchema` = the lesson schema plus a `special` block: `{ slug, group: 'verbs' | 'cases' | 'sentences' | 'words' | 'life', levels: [Level, Level], related: string[] /* lesson ids */, bookRefs: BookRef[] }`. `id` is `sp-<slug>` so progress keys can never clash with lesson ids. `number` is the hub order.
- `specials` is a separate array. It is NOT added to `lessons`, so the learning path, per-level statistics, and lesson-number checks are untouched.
- Two new step kinds, both non-interactive dividers: `chapter` (title, titleFr) groups steps and drives the chapter list on the special's page; `quiz` (title, titleFr, passMark, default 0.8) marks the start of the final quiz — every exercise step after it is a quiz question. Everything the main player already renders (intro, vocab, grammar, exercise, pronunciation, wrapup) is reused. Every code path that switches on step kind (StepPlayer, stepId, LessonStepNav, audio collection, tests) must handle the new kinds; the plan lists them.
- `BookRef.lektion` becomes optional so DaF/Easy German references (no Lektion) fit the same shape.
- Grammar notes use MiniMarkdown (bold and bullets only; no tables). Tables, such as paradigms, use the existing `conjugation-table` diagram or are written as aligned bullet lists. The plan checks what the diagram supports and adds a minimal table-note step kind only if two or more specials truly need it.

### 2. Structure of one special

Intro (goals, scene) → 4–6 chapters, each: grammar/word-field notes with examples, then vocab or pronunciation steps where relevant, then 3–6 practice exercises → wrapup (summary card) → `quiz` marker → 12–15 mixed questions (at least three exercise types) → results.

- Pass: quiz score ≥ 80% (derived, see §4). The results screen shows pass/fail, the missed items and a retake button.
- Related: `related` lesson ids render as chips on the special's page and, reversed, as a "Related special" chip on the intro/wrapup steps of those lessons.
- Book refs render through the existing `BookRefLinks` as "More in the textbook" (links open the preview reader at those pages).

### 3. Placement

- New nav item "Specials" → `/specials` (hub). The nav then has 8 items; the plan checks fit at tablet width and moves the least-used link into the drawer if it overflows. Footer link added.
- Hub (`/specials`): group filter, level chips (A1/A2/B1), a card per special showing title, level, chapter count, progress ring and a "Passed" badge; a "Continue" card for the special in progress.
- Special page (`/specials/<slug>`): overview with goals, chapter list (with completion ticks), quiz description and pass mark, related lessons, textbook links, Start/Continue.
- Learning: `/specials/<slug>/learn` renders `StepPlayer` with the special as the lesson. `StepPlayer` gets an optional `exitHref` (default `/`) so Close and "finish" return to the special's page. `/specials/<slug>/review` reuses the lesson review for wrong answers.
- Home: a "Specials" row between the due-today card and the learning path, showing 4 specials (continue first, then suggested by the learner's level).
- Statistics: count of specials passed and per-group progress.
- All new strings go in `lib/ui-strings.ts` (EN+FR).

### 4. Progress, XP and pass state

- Reuse `useProgress`: `markStepDone`, `answerExercise`, `completeLesson` all take an id string, so `sp-<slug>` works with no new persisted fields.
- Passed = quiz exercise ids all answered and the correct share ≥ `passMark`, derived from `state.lessons[id].exercises`. Nothing new is persisted, so Supabase sync and `normalizeProgress`/`mergeProgress` need no change. The plan confirms how a retake overwrites earlier results (`withExerciseResult`) and, if a failed attempt can't be replaced, adds the smallest fix.
- Completing a special awards the lesson XP once (existing guard in `completeLesson`); a pass does not award extra XP in v1.

### 5. Audio and vocabulary

- `allVocab()` includes special vocab (so hard-word lookup works); `vocabByLevel()` does not (the textbook word grid keeps its current scope). Vocab ids are prefixed `sp-<slug>-…` to stay unique.
- `scripts/prepare-audio.mjs` (`collectAudioJobs`) iterates `specials` as well as `lessons`; `npm run audio` generates the mp3s. Any spoken text not covered 404s, so a test asserts that every `ttsText` and vocab example in specials has an audio job.

### 6. Authoring

- Content is written in batches by agents, each given: the topic row above, the original-content rule, EN+FR, the schema, two finished specials as style references, and the list of related lessons so explanations link rather than repeat.
- Each batch is verified before merge: load-time Zod parse, coverage test, a proofreading pass (like the lesson proofread), and spot-checking against a standard reference for grammar accuracy.
- Quality bar per special: every grammar note has examples with EN and FR translations; exercises have an `explain` (or hint) wherever the answer is a rule; quiz questions are not copied from chapter exercises.

## Rollout

1. Engine: schema, two new step kinds, `specials` registry, routes, hub, special page, `exitHref`, nav/home/footer/stats strings, audio hook, coverage test.
2. Four pilot specials, covering both a grammar and a word-field special: Modalverben, Konjunktiv II, Farben & Kleidung, Wortstellung. Review these with the user before scaling.
3. The remaining 28 in parallel batches, then audio generation, then a browser pass at 1280×800 and 375×812.
4. Deploy only when asked.

## Verification

- Coverage test (Vitest) over `specials`: unique ids and slugs with the `sp-` prefix; at least 25 specials; 4–6 chapters each; a `quiz` step followed by at least 12 exercise steps of at least 3 types; EN and FR present on every title, goal, note, example and exercise prompt; `related` ids exist in `lessons`; book ids exist in `BOOKS`; vocab ids unique; every spoken string has an audio job.
- Unit tests for pass-state derivation (pass, fail, retake) and the reverse related-special index.
- Step-kind exhaustiveness: TypeScript `never` checks in each switch.
- Browser: hub filters, start → complete → quiz fail and pass, badge, retake, mobile sticky bars, nav fit, a special linking back to its lessons and book pages.

## Risks

- Overlap with the main lessons means duplicated explanations; mitigated by linking and by giving each special a distinct angle (reference + drills).
- Authoring volume is large (32 specials × about 25 steps plus audio); mitigated by pilots first and per-batch validation.
- Book page references: DG and EG pages are from their outlines and PONS needs a manual pass; the plan includes a verification pass in the reader.
- Copyright: the books are referenced, never reproduced; reviewers check new text for closeness to the sources.
